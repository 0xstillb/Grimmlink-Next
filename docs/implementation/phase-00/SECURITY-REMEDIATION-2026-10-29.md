## 3. R-02 — No-Fork Native KOSync security feasibility
- Pinned [KoreaderAuthFilter:33–80](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/config/security/filter/KoreaderAuthFilter.java#L33-L80) accepts x-auth-user/key (MD5), maps `BookLoreUserId` in KO principal. That is **not a REST JWT**.
- [KoreaderService:48–95,271–293](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/service/koreader/KoreaderService.java#L271-L293) uses global `findByCurrentHash`, then a user-scoped row. [BookAccessAspect:31–68](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/config/security/aspect/BookAccessAspect.java#L31-L68) enforces assigned libraries and content restrictions only when invoked through annotated handlers; Native KOSync progress handler is unannotated. [SecurityConfig:125–135](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/config/security/SecurityConfig.java#L125-L135) separates KO security filter chain.
- Same-user candidate: user-consented Official login JWT → `GET /api/v1/users/me` and `GET /api/v1/koreader-users/me`, validate immutable user identity, KO profile, no credential fields output; independent KO auth proof via Official `GET /api/koreader/users/auth`, never identity by string alone. JWT/refresh vaulted and encrypted; revoke on logout, rotation, failed refresh, KO password change and entitlement changes. Per request private same-user `GET /api/v1/books/{bookId}` with @CheckBookAccess plus explicit exact hash, bookFileId and edition mapping.
- **TOCTOU remains unclosed:** Official Native PUT does not share atomic authorization/transaction with Adapter preflight; ACL can be revoked between them. Therefore **NATIVE_KOSYNC_PROGRESS = BLOCKED/OFF**. A pre-check is **not** atomic enforcement. No fork introduced, no admin surrogate, no native progress passthrough via unknown alias. Alternative: read-only/no Native KO progress while app's native REST UI stays behind reviewed policy; optional future adapter-managed progress only with independently enforceable atomic semantics and single-writer proof — NOT an accepted replacement yet.
- Detailed ADR: [ADR-025 Native KOSync security](../ADR-025-NATIVE-KOSYNC-SECURITY.md). `SOURCE_VERIFIED` facts, `DESIGN_SPECIFIED` candidate; no `IMPLEMENTED_VERIFIED` or `DEPLOYED_VERIFIED`.

## 4. R-01 — precise payload builder / metadata safety
[BookMetadata DTO:18–132](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/model/dto/BookMetadata.java#L18-L132) and [BookMetadataUpdater:108–117,177–245](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/service/metadata/BookMetadataUpdater.java#L177-L245) confirm that scalar lock bits are not safe from a silent bypass; upstream [MetadataController:51–59](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/controller/MetadataController.java#L51-L59) defaults `replaceMode=REPLACE_ALL`. **Builder**: closed object schema; reject unknown OPF-to-DTO mapping and unknown keys, `allMetadataLocked`, every `*Locked`, `clearFlags` with any true, `bookReviews:[]` and any `authors/categories/moods/tags/bookReviews` even empty/null, all nested DTOs, IDs, provider, covers. Reject null/empty values in submitted payload (skip at OPF ingestion ONLY, not forward), empty change set, ambiguous or stale source. Emit `PUT /api/v1/books/{id}/metadata?replaceMode=REPLACE_WHEN_PROVIDED&mergeCategories=false` with `{metadata:<allowed nonempty scalars>,clearFlags:<all-false-or-omitted>}`; explicit operator-approved fingerprint includes user, bookId, bookFileId, edition, original OPF SHA256, source mount, target old-value/locks, diff, expiry. Re-read exact OPF and Official GET just before PUT, reject changed fingerprint or any lock, verify unchanged NAS/Sidecar/embedded-write/move settings and RO mount; only send with authorized same editing identity, no admin substitution. Post-PUT same-user readback matches every key. Network uncertain means `UNCERTAIN_METADATA_WRITE`, no blind retry. Revalidation is **optimistic, NOT atomic CAS**. Concurrent edit between GET/PUT remains residual; if zero-lost-update guarantee demanded, metadataApply remains OFF unless upstream API offers atomic preconditions. Current status `metadataApply=OFF`; Phase03 isolated mocks then Phase09 real settings/E2E.

## 5. R-09 — durable session outbox and ACK uncertainty
[ReadingSessionController:28–36](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/controller/ReadingSessionController.java#L28-L36) responds HTTP 202; [ReadingSessionService:125–150](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/service/ReadingSessionService.java#L125-L150) inserts a row **without an eventId idempotency constraint**. `eventId=SHA256(version,userId,bookId,deviceId,immutable session UUID)`; SQLite WAL + UNIQUE(eventId) with immutable payload digest; persist NEW→SENDING attemptCount=1 in durable transaction/fsync BEFORE network; exactly one dispatcher claim; disable HTTP-client/proxy transparent retries and hidden retry policies; crash after SENDING (including before actual send) or lost 202 ⇒ terminal `UNCERTAIN` (never auto retry). Observed 202 ⇒ `ACKED_202` (not exactly-once); duplicate same key/payload returns stored outcome, different payload ⇒ CONFLICT. Optional same-user GET reconciliation yields `RECONCILED_MATCH` **not a cryptographic receipt**. Accept explicit **at-most-once dispatch, possible lost event**. `sessionsBridgeWrite=OFF` until Phase07 isolated durable crash tests/approval.
