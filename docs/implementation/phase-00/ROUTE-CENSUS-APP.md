- [AppNotebookService:38–159](https://github.com/grimmory-tools/grimmory/blob/402e89b4452f8e2b17ab95f16c1621c003516cd2/backend/src/main/java/org/booklore/app/service/AppNotebookService.java#L38) uses caller user ID in notebook listing/entry queries, and delegates PUT/DELETE to annotation, note and bookmark services. **Do not confuse row user scoping with per-book current entitlement or delegate's per-item ownership**; inspect underlying services and repository predicates before allowing a mutation.
- App shelf GET reads user/public shelves; public-list visibility does not prove every returned book is currently entitled. App author/series/filter/library endpoints require per-endpoint data-leakage review.
- No `@CheckBookAccess` appears at the inspected AppBook/AppNotebook method annotations. Do not generalize this to no authorization: services may enforce assigned-library and item rules.
- Required negative cases: revoked library, restricted content, foreign entry, stale personal row, duplicate/unknown book, no-existence leak, read vs mutation, invalid type, progress file mismatch.
- All App Gateway sensitive handling is **DESIGN_SPECIFIED**, NOT_RUN; Official UI compatibility must use explicit reviewed routes, never a wildcard sensitive passthrough.
