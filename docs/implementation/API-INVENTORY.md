## Phase02 gateway authorization boundary — design gate, not source/API proof

Official `/api/koreader/**` authenticates KOSync headers, while `KoreaderService.findBookByHash` uses global hash lookup; its inspected service does not establish assigned-library/content checks for that user. A default proxy of Official progress GET/PUT is therefore **NOT** accepted. All exposed progress routes (canonical and aliases) must first pass a deny-by-default Adapter authorization gateway with matched user, exact book/file digest and same-user library/content entitlement; without proof return denial **before** reaching Official. Ensure the upstream 6060 path cannot be reached through a bypass; never translate a KOSync MD5 credential to a different user's/admin REST identity. Personal bookmarks/annotations/session/status/rating routes need the same caller/book/record proof before bridge writes. This is an unverified design condition, not an assertion of an existing vulnerability or an implemented protection. [KOSync controller](https://github.com/grimmory-tools/grimmory/blob/v3.5.0/backend/src/main/java/org/booklore/controller/KoreaderController.java#L39-L58), [security chain](https://github.com/grimmory-tools/grimmory/blob/v3.5.0/backend/src/main/java/org/booklore/config/security/SecurityConfig.java#L125-L135), [hash lookup](https://github.com/grimmory-tools/grimmory/blob/v3.5.0/backend/src/main/java/org/booklore/service/koreader/KoreaderService.java#L271-L293), [book access aspect](https://github.com/grimmory-tools/grimmory/blob/v3.5.0/backend/src/main/java/org/booklore/config/security/aspect/BookAccessAspect.java#L31-L68).
