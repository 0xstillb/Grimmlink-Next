## Runtime boundaries
- One published host port **6060**, with existing reverse proxy preferred; Official UI/API/OPDS routes remain intact, `/grimmlink/*` and `/api/grimmlink/v2/*` terminate at the internal Adapter. `/api/koreader/users/auth` and `/users/create` require explicit routing/auth policy; **all external KOSync progress GET/PUT must be default-denied at the gateway until a user-bound, book-entitlement verifier is implemented and proven**. Intercept/alias paths only after checking Readest/KOReader base URLs, and prevent any alternate prefix or direct upstream port bypass. A design-only OFF flag is not an active deny rule. Internal container ports must not be separately published.
- TypeScript/Node LTS + Fastify backend, SQLite/Drizzle durable local ownership (device/hash mapping, verified positions, outbox, dedupe, job receipts); React/Vite UI static served by Fastify behind same gateway. Official Grimmory is authoritative for library metadata and supported per-user data.
- NAS input: mounted NETWORK disk in Grimmory, Adapter **RO**; no rename/move/delete/repack of source EPUB/PDF/OPF. NAS identity/sentinel and path containment are prerequisites; empty/missing mount is not an empty library. Ensure Grimmory source-write-related settings are explicitly OFF and audited (metadata file write, sidecar export, move-on-update), rather than assuming NETWORK removes all writes.
- OPF adjacency is primary; scan ALL_BOOKS_WITH_OPF; validate XML/path/symlinks/cover MIME/hash; immutable diff and staleness validation; user-reviewed dry-run, then per-book API apply and read-back. Cover is a **separate** upload and verification receipt.
- Explicit `replaceMode=REPLACE_WHEN_PROVIDED` on every metadata PUT and explicit `clearFlags` all false by default; an approved clear requires a separately reviewed operation. **Only known nonempty scalar OPF fields may enter the default payload**; omit null/blank scalar values, **all collections** (`authors`, `categories`, `moods`, `tags`, `bookReviews`), all `*Locked` fields, nested comic/relationship objects and unknown properties. Never transmit `bookReviews: []`: the Official review updater can clear old reviews regardless of `replaceMode`. Missing/empty OPF values are not a general non-destructive guarantee for submitted collections. Collections require separately approved whole-set diff, verified locks, explicit merge/replace policy, payload fingerprint and readback; otherwise SKIP. The server default `REPLACE_ALL` is unsafe.
- Sidecar inspect/optional fallback/backup/preview/restore **only with verified safe read-only semantics**. Sidecar export is NOT a read-only preflight (it may write JSON). No adjacent NAS write, Sidecar export, original-file rewrite or auto-move in normal sync; any future RW workflow requires separate explicit authorization and audit.
- Use native KOSync first; explicitly separate its MD5 header identity from Official JWT REST. User-scoped API operations must never be performed as an unrelated admin. Managed KOSync, exact book digest and CFI projection require new proof.
- Preserve native location untouched when conversion cannot resolve exactly. `@prose-reader/koreader` is an **investigated** converter; do not ship `CHAPTER_ONLY` as `EXACT`; never invent percentages. Official Continue Reading at zero percent is an accepted UI limitation. Readest OPDS is add-only, not full shelf sync.
- Pino JSON logs / correlation IDs, secrets and private notes redaction, DEBUG ≤30m, TRACE ≤5m, reproducible diagnostics. Version watcher only proposes; manual approval + verified backup/rollback for update.
- Phases 00–08 allow source, static, JSON, unit, mocks and isolated fixture checks; **all** full integrated E2E, Hermes/NAS real stack, physical devices and production acceptance strictly Phase 09.

## Explicit Phase02 access-control gateway contract (design only)

Until the implementation can prove the following on every request, **deny external `GET /api/koreader/syncs/progress/{bookHash}` and `PUT /api/koreader/syncs/progress` before proxying to Official**; unknown aliases, duplicate prefixes and direct upstream access are denied. `x-auth-user`/MD5 authentication alone is **not** library authorization. For an allowed request, bind authenticated KOSync identity to one provisioned Grimmory user (not an admin surrogate), validate the exact book hash against an immutable user/book/file mapping, and prove assigned-library AND content-restriction entitlement for that user and edition before GET or PUT. Reject unknown mappings, cross-library, restricted content, user mismatch, ambiguous hashes, replay/conflict and unverifiable entitlement without forwarding or writing; do not leak existence through response differences. An authentication success or upstream 200 is not authorization proof. The implementation MUST ship its own deny-by-default gateway rule and negative tests in Phase02/05; Phase00 documents no deployed enforcement. Similarly gate all personal REST CRUD/status/rating/session operations by bound caller, book entitlement and record ownership before proxying, with no admin impersonation. If such proof is unavailable under Official no-fork constraints, leave the capability OFF and escalate a **BLOCKED design** before enabling.
