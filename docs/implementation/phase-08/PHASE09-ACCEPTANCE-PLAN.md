# Phase 09 Acceptance Plan — Single-Owner Private

**Status: STAGING_HOST_CONFIRMED_BY_OWNER; DEPLOYMENT_AND_TESTS_NOT_RUN.** The existing Staging machine is waiting for a code candidate. This document prepares that deployment and test run; it is not test evidence, permission to connect production, or authorization to enable a protected route. Full-stack, NAS, Hermes and physical-reader tests remain Phase09-only.

## Entry conditions

- Record the exact candidate commit and pinned Grimmory, Adapter, KOReader and Readest versions before testing.
- Deploy to the existing owner-confirmed Staging machine and use its isolated Grimmory instance, a disposable single-owner account, a dedicated read-only NAS fixture and non-sensitive test books. Do not provision a duplicate environment or use a production library or real private annotations.
- Capture a verified backup and checksums before any operation that can mutate state. Keep all feature switches OFF until the individual scenario has passed its prerequisite checks.
- Use at least two independently paired reader devices to exercise same-owner multi-device behavior. Record device model, OS/KOReader version and app build.
- Sanitize evidence before storage. Never retain passwords, bearer/device tokens, KO credentials, book text, notes or private annotations in logs, screenshots or artifacts.

## Stop conditions

Stop the scenario and leave the affected capability OFF if ingress bypasses the intended gateway; owner or book/file binding is uncertain; the NAS is writable or changes source bytes; a metadata field would be cleared or replaced without an approved diff; an outcome is uncertain after dispatch; a position cannot be proven exact; a token or private content enters logs/artifacts; a package signature/compatibility check fails; or rollback cannot restore the pre-test state.

## Evidence record

For each scenario record: scenario ID, UTC start/end, exact code and dependency versions, staging identity (non-secret), device/runtime versions where applicable, command or manual steps, expected and observed result, exit code, sanitized evidence paths and SHA-256 values, any state delta, disposition, and remediation link. Mark unrun scenarios `NOT_RUN`; do not infer a pass from mocks or CI.

## Release gate

The release candidate is accepted only after required Phase09 scenarios pass at one exact candidate SHA, all applicable deferred findings are fixed or explicitly rejected by the owner with rationale, the consolidated independent review verifies the actual diff and evidence, and the owner explicitly approves release. This plan does not authorize merging to `main`, enabling production routes, or publishing an update.
