## NEW-R2-01 — Incomplete safety-map invariant in Phase00/Phase01 machine gate (HIGH)

**Files/lines:** `scripts/phase-00/validate-phase00-release-gates.py:62-92`, `docs/implementation/ACTIVE-SESSION.json:41-50`, `scripts/phase-00/test_release_gate_integrity.py:59-83`.

The validator insists that `current["safety"]["officialGatewayForwarding"] == "DENY_ALL"` and exact-matches all values in `current["securityCapability"]`, but never verifies the **other independent safety fields**: `nativeKosyncProgress`, `metadataApply`, `personalBridge`, `sessionBridge`, `resetProgress`, `managedProjection`, `productionDeployment`, `fullE2ePhase`.

**Non-mutating counterexample at the pinned HEAD:** Clone the in-memory ACTIVE-SESSION object and set:
```json
{
  "safety": {
    "metadataApply": "ON",
    "personalBridge": "ON",
    "productionDeployment": "AUTHORIZED"
  }
}
```
Leaving the existing `officialGatewayForwarding`, `securityCapability`, `phase` and `phaseStatus` unchanged still satisfies every `ACTIVE-SESSION` safety predicate currently implemented in the validator (its only `safety` read is the gateway-forwarding field). The source ledger and review-hash checks do not read those other safety fields. This was verified by a **read-only logic reproduction**, not by writing to the live repo or running its complete Python validator against mutated files.

**Risk:** An inconsistent/misleading design-only release-gate document could produce a false-green Phase00 integrity check while sensitive statuses in the separate `safety` map are marked enabled. This is **not proof that a real runtime gateway or personal bridge is enabled**; Phase01 currently has no upstream transport routes.

**Required fix:** Exact-compare an approved `safety` map (or all required fields with strict values and reject unknown keys), in addition to the `securityCapability` map. Add negative tests for `metadataApply="ON"`, `personalBridge="ON"`, `productionDeployment="AUTHORIZED"`, and unknown extra safety keys. Cross-check that both maps represent the same blocked states. Re-run exact-head Phase00 and Phase01 CI.
